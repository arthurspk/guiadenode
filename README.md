## 🎯 Sobre este guia
Node.js é o ambiente que executa **JavaScript fora do navegador**: criado em 2009 sobre o motor V8 do Chrome e mantido hoje pela OpenJS Foundation, ele roda APIs, sites, ferramentas de linha de comando, bots e o tooling de praticamente todo o ecossistema web (npm, bundlers, frameworks). Seu modelo assíncrono e orientado a eventos permite atender muitas conexões ao mesmo tempo com poucos recursos — por isso é a tecnologia de back-end mais pedida nas vagas de JavaScript no Brasil.

O Node.js de 2026 é bem diferente do de alguns anos atrás: a versão **24 é a LTS ativa** (a 22 está em manutenção, a 20 chegou ao fim da vida em abril e a **26** vira LTS em outubro), e coisas que antes exigiam bibliotecas agora vêm de fábrica — `fetch`, `node --test`, `node --watch`, `--env-file`, `node:sqlite`, **execução nativa de TypeScript** (type stripping) e o **modelo de permissões** (`--permission`).

Este guia é para quem já sabe (ou está aprendendo) JavaScript e quer usar Node.js para construir back-ends e ferramentas, do `node ola.js` ao deploy. Os recursos em português e gratuitos vêm primeiro em cada seção; quando um recurso é pago ou está em inglês, isso é indicado no texto da descrição. Todo link foi verificado na data da última revisão.

## 🗺️ Roadmap
- [roadmap.sh — Node.js Developer Roadmap](https://roadmap.sh/nodejs) — Roadmap visual e interativo da comunidade, em inglês: módulos nativos, npm, frameworks, testes, deploy — com links por tópico.
- [roadmap.sh — Backend Developer Roadmap](https://roadmap.sh/backend) — O caminho completo de back-end (HTTP, bancos, APIs, cache, segurança) no qual o Node.js se encaixa, em inglês.
- [Introduction to Node.js (Node.js Learn)](https://nodejs.org/learn/getting-started/introduction-to-nodejs) — Página oficial em inglês que explica o que é o Node.js, por que é assíncrono e como rodar o primeiro servidor.
- [Sobre o Node.js (site oficial em português)](https://nodejs.org/pt-br/about) — Apresentação oficial traduzida: modelo orientado a eventos, I/O não bloqueante e exemplo de servidor HTTP.
- [Node.js Reference Architecture (Red Hat e IBM)](https://nodeshift.dev/nodejs-reference-architecture/) — Opinião de dois times que rodam Node.js em produção, em inglês: quais pacotes e práticas escolher para cada necessidade.

**Trilha resumida** (siga na ordem; cada etapa tem recursos nas seções abaixo):

1. **JavaScript moderno (ES6+)** — `let/const`, arrow functions, destructuring, módulos ES, `Promise`/`async-await`. Sem isso, Node.js vai parecer só "erro de callback".
2. **Fundamentos do runtime** — instalar a versão LTS, `node`/`npm`/`npx`, `package.json`, módulos CommonJS × ESM, o event loop e por que I/O é assíncrono.
3. **Módulos nativos** — `fs`, `path`, `http`, `events`, `stream`, `child_process`, `process`, `fetch`, `node:test`.
4. **APIs HTTP** — REST com Express ou Fastify: rotas, middlewares, validação (Zod), tratamento de erros, autenticação (JWT).
5. **Dados** — PostgreSQL ou MongoDB com um ORM/ODM (Prisma, Drizzle, Mongoose), migrations, variáveis de ambiente.
6. **Qualidade** — testes (`node --test`, Vitest ou Jest), ESLint/Biome, TypeScript, logs estruturados (Pino), debugging com `--inspect`.
7. **Produção** — Docker, PM2 ou containers, deploy (Render, Railway, Fly.io), segurança (Helmet, `npm audit`, Permission Model), monitoramento.
8. **Avançado** — streams e backpressure, workers e cluster, filas (BullMQ), WebSockets, arquitetura (Clean Architecture, NestJS), performance (Clinic.js, autocannon), contribuir com o core.

## 🚀 Por onde começar
1. **Domine o JavaScript primeiro.** Use o [Guia de JavaScript da MDN (PT-BR)](https://developer.mozilla.org/pt-BR/docs/Web/JavaScript) ou o [Curso de JavaScript 2024 do Matheus Battisti](https://www.youtube.com/playlist?list=PLnDvRpP8BnexyabTa4NQrLy3s5NowwAxb) — Node.js é JavaScript por baixo.
2. **Instale a versão LTS** pela [página oficial de download](https://nodejs.org/pt-br/download) (ou com [nvm](https://github.com/nvm-sh/nvm)/[fnm](https://github.com/Schniz/fnm) para trocar de versão) e o [Visual Studio Code](https://code.visualstudio.com/).
3. **Entenda o que é o Node** lendo a [introdução oficial](https://nodejs.org/learn/getting-started/introduction-to-nodejs) (em inglês) e o [artigo da Alura sobre o loop de eventos](https://www.alura.com.br/artigos/arquitetura-node-js-entenda-loop-de-eventos) (PT-BR).
4. **Faça um curso rápido:** [Felipe Rocha](https://www.youtube.com/watch?v=IOfDoyP1Aq0) (aula única) ou o [Curso de Node.js 2025 da Stack Mobile](https://www.youtube.com/playlist?list=PLizN3WA8HR1w14FUaPYsP9q1nBHuTa1Dv).
5. **Aprofunde com um curso completo:** [Node.js do Matheus Battisti](https://www.youtube.com/playlist?list=PLnDvRpP8BneyHealXbzntUoFtE4SrFWWW) ou, se já quiser TypeScript, [Do zero a produção (Waldemar Neto)](https://www.youtube.com/playlist?list=PLz_YTBuxtxt6_Zf1h-qzNsvVt46H8ziKh).
6. **Construa sua primeira API** seguindo o [tutorial de Express da MDN em português](https://developer.mozilla.org/pt-BR/docs/Learn_web_development/Extensions/Server-side/Express_Nodejs) e teste-a com [Bruno](https://www.usebruno.com/) ou [Hoppscotch](https://hoppscotch.io/).
7. **Escreva testes desde cedo** com o [test runner nativo](https://nodejs.org/learn/test-runner/using-test-runner) — sem instalar nada.
8. **Publique um projeto** no GitHub e no ar ([Render](https://render.com/) ou [Railway](https://railway.com/)); depois encare um desafio do [backend-br](https://github.com/backend-br/desafios) ou a [Rinha de Backend](https://github.com/zanfranceschi/rinha-de-backend-2025).

Seu primeiro servidor em 30 segundos (sem instalar nenhum pacote):

```bash
mkdir ola-node && cd ola-node
npm init -y
```

```js
// servidor.js
import { createServer } from "node:http";

createServer((req, res) => {
  res.setHeader("Content-Type", "application/json; charset=utf-8");
  res.end(JSON.stringify({ mensagem: "Olá, Guia Dev Brasil!" }));
}).listen(3000, () => console.log("http://localhost:3000"));
```

```bash
node --watch servidor.js        # reinicia sozinho quando o arquivo muda
```

```js
// servidor.test.js
import { test } from "node:test";
import assert from "node:assert/strict";

test("responde com JSON", async () => {
  const res = await fetch("http://localhost:3000");
  assert.equal((await res.json()).mensagem, "Olá, Guia Dev Brasil!");
});
```

```bash
node --test                     # test runner nativo (com o servidor rodando)
node servidor.ts                # Node.js 22.18+/24 executa TypeScript direto (type stripping)
node --permission --allow-fs-read=. servidor.js   # modelo de permissões
```

> Dica: para usar `import` como acima, coloque `"type": "module"` no `package.json` ou salve os arquivos como `.mjs`.

## 🛠️ Ferramentas
### Runtime, versões e pacotes
- [nvm](https://github.com/nvm-sh/nvm) — Gerenciador de versões do Node para macOS/Linux: troque de versão com `nvm use`.
- [nvm-windows](https://github.com/nvm-windows/nvm) — O gerenciador de versões equivalente para Windows.
- [fnm](https://github.com/Schniz/fnm) — Gerenciador de versões rápido, escrito em Rust, multiplataforma.
- [Volta](https://volta.sh/) — Fixa a versão de Node e npm por projeto automaticamente.
- [pnpm (docs em português)](https://pnpm.io/pt/) — Gerenciador de pacotes rápido e econômico em disco, padrão em monorepos.
- [Yarn](https://yarnpkg.com/) — Gerenciador de pacotes alternativo, com workspaces e plug'n'play.
- [Corepack](https://github.com/nodejs/corepack#readme) — Gerencia a versão do pnpm/Yarn declarada no `package.json` (`packageManager`).
- [tsx](https://github.com/privatenumber/tsx) — Execute TypeScript com `enum`/`namespace` e sem configuração quando o type stripping nativo não basta.
- [TypeScript](https://www.typescriptlang.org/) — Tipos estáticos para o Node; hoje o padrão em projetos profissionais.
- [Bun](https://bun.sh/) — Runtime alternativo ultrarrápido, compatível com a maior parte das APIs do Node.
- [Deno](https://deno.com/) — Runtime seguro por padrão, com TypeScript nativo e compatibilidade com npm.
- [Imagem oficial do Node no Docker Hub](https://hub.docker.com/_/node) — Tags `node:24-alpine`, `node:22-slim` etc. para containerizar sua aplicação.
- [nodejs/docker-node — boas práticas](https://github.com/nodejs/docker-node) — Repositório da imagem oficial, com guia de boas práticas para Dockerfile em Node.

### Frameworks, bancos de dados e bibliotecas
- [Express](https://expressjs.com/pt-br/) — O framework web mais usado do Node; minimalista e com documentação em português.
- [Fastify](https://fastify.dev/) — Framework rápido e extensível, mantido por membros do core do Node.
- [NestJS](https://docs.nestjs.com/) — Framework opinativo em TypeScript (módulos, injeção de dependência), muito comum em empresas.
- [Hono](https://hono.dev/) — Framework pequeno baseado em Web Standards; roda em Node, Bun, Deno e edge.
- [Koa](https://koajs.com/) — Framework minimalista dos criadores do Express, baseado em `async/await`.
- [AdonisJS](https://adonisjs.com/) — Framework full stack "com pilhas incluídas" em TypeScript (ORM, auth, validação).
- [hapi](https://hapi.dev/) — Framework focado em configuração e segurança, usado em grandes empresas.
- [Socket.IO](https://socket.io/) — Comunicação em tempo real (WebSocket com fallback) entre servidor Node e clientes.
- [Prisma](https://www.prisma.io/) — ORM com cliente totalmente tipado gerado a partir do schema; ótimo para começar.
- [Drizzle ORM](https://orm.drizzle.team/) — ORM leve, TypeScript-first, com sintaxe próxima do SQL.
- [TypeORM](https://typeorm.io/) — ORM baseado em decorators, comum em projetos NestJS.
- [Sequelize](https://sequelize.org/) — ORM veterano para bancos relacionais (PostgreSQL, MySQL, SQLite…).
- [Knex.js](https://knexjs.org/) — Query builder SQL com migrations, para quem prefere escrever SQL.
- [Mongoose](https://mongoosejs.com/) — ODM para MongoDB com schemas e validação.
- [Zod](https://zod.dev/) — Validação de dados com inferência de tipos — valide `body`, `query` e variáveis de ambiente.
- [Undici](https://undici.nodejs.org/) — O cliente HTTP oficial do Node que implementa o `fetch` global.
- [BullMQ](https://docs.bullmq.io/) — Filas e jobs em background com Redis.
- [Nodemailer](https://nodemailer.com/) — Envio de e-mails a partir do Node, com SMTP e provedores.
- [Passport.js](https://www.passportjs.org/) — Autenticação com centenas de estratégias (local, OAuth, JWT).
- [jsonwebtoken](https://github.com/auth0/node-jsonwebtoken) — Geração e verificação de JWT, a biblioteca mais usada para tokens.
- [Helmet](https://github.com/helmetjs/helmet) — Cabeçalhos HTTP de segurança para apps Express em uma linha.
- [Multer](https://github.com/expressjs/multer) — Upload de arquivos (`multipart/form-data`) no Express.
- [dotenv](https://github.com/motdotla/dotenv) — Carrega `.env` em `process.env` (o Node moderno também faz isso com `--env-file`).
- [Commander.js](https://github.com/tj/commander.js) — Crie ferramentas de linha de comando em Node com parsing de argumentos.
- [Puppeteer](https://pptr.dev/) — Controle o Chrome a partir do Node para scraping, PDFs e automação.
- [Playwright](https://playwright.dev/) — Automação e testes end-to-end de navegador, da Microsoft.
- [json-server](https://github.com/typicode/json-server) — API REST fake em 30 segundos a partir de um JSON — ótimo para prototipar front-ends.

## 🤖 IA na prática
Node.js e assistentes de IA combinam por dois motivos: o ecossistema é gigantesco (a IA conhece Express, Prisma e `node:test` de cor) e o runtime dá **feedback imediato** — você roda o código, o teste ou o `npm audit` e descobre em segundos se a sugestão estava certa. Use isso a seu favor.

**Para aprender**
- Cole um erro real (ex.: `Error [ERR_REQUIRE_ESM]`, `UnhandledPromiseRejection`, `EADDRINUSE`) junto com o trecho de código e peça: *"explique a causa, mostre a correção e diga como evitar de novo"*.
- Peça para **explicar o event loop com um exemplo executável** usando `setTimeout`, `setImmediate` e `process.nextTick`, rode com `node` e confira se a ordem impressa bate com a explicação.
- Peça um **projeto guiado em etapas** ("API de tarefas com Express, validação com Zod e testes com `node:test`") e implemente cada etapa antes de pedir a próxima.
- Peça para **converter um código com callbacks para `async/await`** e depois para explicar o que mudou no tratamento de erros.
- Peça **exercícios com gabarito** sobre o módulo que está estudando (`fs`, `stream`, `http`, `events`).

**Para trabalhar**
- Use [GitHub Copilot](https://github.com/features/copilot), [Cursor](https://cursor.com/) ou [Claude Code](https://code.claude.com/docs/en/overview) para: escrever testes de integração com SuperTest, gerar um `Dockerfile` multi-stage, migrar CommonJS → ESM, atualizar uma API do Express 4 para o 5, ou documentar rotas em OpenAPI.
- Depois de **cada** sugestão aceita, rode `node --test` (ou Vitest), o linter e `npm audit`. Se a IA sugerir instalar um pacote, confira no [npm trends](https://npmtrends.com/) se ele existe, é mantido e tem downloads — **pacotes inventados por IA são um vetor real de ataque** (slopsquatting).
- Prefira os recursos nativos que a IA às vezes não conhece por serem recentes: `fetch` no lugar de axios, `node --test` no lugar de Jest, `--env-file` no lugar de dotenv, `--watch` no lugar de nodemon.

**Limites e boas práticas**
- IA **mistura versões**: pode sugerir `require()` em projeto ESM, APIs removidas ou flags experimentais como se fossem estáveis. Confirme na [documentação da API](https://nodejs.org/docs/latest/api/) da sua versão.
- Ela tende a ignorar `await` esquecido, vazamento de listeners, backpressure em streams e `process.exit()` no meio do código. Leia o que aceita.
- Não cole segredos (`.env`, tokens, strings de conexão), dados de clientes ou código proprietário em ferramentas sem a política da sua empresa.
- Em entrevista e em produção, o código é seu: entenda cada linha.

**Node.js é o runtime da IA aplicada.** Os SDKs, frameworks de agentes e o Model Context Protocol têm implementações oficiais em JavaScript/TypeScript que rodam em Node — aprender Node abre a porta para construir produtos com LLMs:
